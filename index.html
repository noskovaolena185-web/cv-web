Проєкти, у яких я працювала з веб-технологіями, backend-логікою, C++ та взаємодією між різними частинами застосунку.

Про проєкт

Невеликий застосунок для моніторингу оперативної пам’яті macOS у реальному часі. Дані про вільну та активну пам’ять отримуються через нативний C++ модуль і передаються у браузер через SSE.

На frontend дані обробляються через EventSource, відображаються у числовому вигляді та додаються на live-графік через SmoothieChart.

Що реалізовано
  • Збір memory statistics через macOS Mach API
  • Нативний Node.js addon на C++ через N-API
  • Передача метрик через Server-Sent Events
  • Оновлення даних без перезавантаження сторінки
  • Візуалізація метрик через SmoothieChart
  • Обробка втрати SSE-з’єднання
Technologies
JavaScript Node.js C++ N-API SSE Mach API SmoothieChart
Про проєкт

Курсова робота — 3D-реалізація головоломки «Ханойські вежі» на C++ з використанням OpenGL та GLUT. Програма відображає три стрижні та диски у тривимірній сцені й дозволяє користувачу самостійно виконувати ходи.

Ігрова логіка контролює правильність переміщення дисків і не дозволяє розміщувати більший диск поверх меншого. Після кожного ходу оновлюється стан гри та перевіряється умова перемоги.

Архітектура

Проєкт побудований з використанням OOP. Клас Disk зберігає параметри диска та відповідає за його rendering у 3D-сцені. Клас HanoiBoard зберігає стан стрижнів, обробляє переміщення та перевіряє правила гри.

У main.cpp реалізовано ініціалізацію OpenGL/GLUT, основний цикл програми та обробку подій клавіатури й миші.

Що реалізовано
  • 3D-сцена на OpenGL та GLUT
  • Логіка переміщення дисків між стрижнями
  • Перевірка допустимості кожного ходу
  • Визначення завершення гри
  • Обертання та масштабування камери
  • Керування через клавіатуру та мишу
  • Лічильник ходів та часу гри
  • Збереження статистики у stats.txt
  • Подвійна буферизація для плавного rendering

Про проєкт

Невеликий task manager на vanilla JavaScript. Користувач може створювати задачі, відмічати їх виконаними, видаляти та фільтрувати за статусом.

Стан задач зберігається у LocalStorage, тому список відновлюється після перезавантаження сторінки. Інтерфейс оновлюється через функцію renderTasks().

Логіка

Задачі зберігаються у масиві об’єктів з id, текстом та статусом виконання. Для фільтрації використовується filter(), а взаємодія зі списком обробляється через події click та change.

Що реалізовано
  • Створення та видалення задач
  • Зміна статусу через checkbox
  • Фільтри All / Active / Done
  • Збереження стану у LocalStorage
  • Динамічний rendering через DOM
  • Event delegation
  • Лічильник задач
Technologies
HTML5 CSS3 JavaScript DOM LocalStorage
